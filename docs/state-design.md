# 状態管理・1日ループ設計

## ゲームの目的(現行)

**まきこ(母)の機嫌を30日間なだめ続ける。** 子どもが親の機嫌をうかがう構図。

| キャラ | 立場 | 役割 |
|---|---|---|
| りみっち | プレイヤー。お弁当屋 | 昼の仕事で仕込みとスイーツを調達する |
| まきこ | 母。めんどくさい | 機嫌(mood 0〜100)がクリア条件。要求を遠回しにしか言わない |
| ぴす | 中華料理店で働く | 特技: 今日あったことをまきこに話して取りなしてくれる |
| とよっぴー | **まきこの母** | 顔を出さないと怒り、まきこの機嫌が下がる(板挟み) |

忘却システム(記憶度)は土台として残っており、「機嫌をとる手段が使えるかどうか」を左右する。
記憶度が落ちた相手は取りなしも思い出話もできなくなる。

設計メモの「実装で相談したいこと」3点(①状態管理設計 ②1日ループのステートマシン ③SVG表情差分)への実装と、
スマホ縦持ち前提のUIを含む。

## 3つの設計判断

### 1. 状態は単一の `GameState` + reducer に寄せた

感情ゲージ・記憶度・日数・フェーズは互いに参照し合う(例: たのしい→会話成功率→記憶度)ため、
別々の state に分けると更新順序のバグが必ず出る。1つの reducer に集約し、
UI は `dispatch` と導出値だけを見る形にした。

### 2. 乱数の種を state に入れた

会話成功判定に乱数が必要だが、`Math.random()` を使うと reducer が純関数でなくなり、
同じ状況の再現ができない。種を `state.seed` に持たせ、`nextRandom(seed) -> {value, seed}` で
更新することで、**state をJSONにすれば完全に再現できる**ようにした。
localStorage が使えない前提なので、`exportSave()` で文字列にして手動保存/サーバ送信に回せる。

### 3. 不正なフェーズのアクションは無視(例外にしない)

`gameReducer` は `phase` が合わないアクションを受けたら state をそのまま返す。
連打やアニメ中の入力で落ちるのを避けるため。UI 側は `canEquip` / `canGift` で事前に潰す。

## 1日ループのステートマシン

```
        ┌──────────── sleep (day+1) ────────────┐
        │                                       │
   ┌────▼─────┐  equip   ┌─────┐  work/meet  ┌──▼──────┐  advance  ┌───────┐
   │ morning  │─────────▶│ day │────────────▶│ evening │──────────▶│ night │
   │ 感情装備 │  最大2つ  │二者択一│            │増減の可視化│           │ 贈り物 │
   └──────────┘          └─────┘             └─────────┘           └───┬───┘
                                                                        │ day > 30
                                                                   ┌────▼────┐
                                                                   │ ending  │
                                                                   └─────────┘
```

- **morning**: `equip` で感情を最大2つ選ぶ。選ばずに進めることも可(空配列)。
- **day**: `work`(一人で作業) か `meet`(誰かに会う) の二者択一。ここで乱数を1回消費する。
- **evening**: 増減は `state.pending: DayResult` に入れてある。差分・段階変化・収穫がすべて含まれるので、
  演出はこれを読むだけでよい(記憶度の再計算をUI側でしない)。
- **night**: **6択から1つだけ**。`giveSweets`(スイーツ) / `pisuTalk`(ぴすに取りなしてもらう) /
  `rest`(休む) / `gift`(贈り物) / `showKeepsake`(思い出の話) / `whisper`(とよっぴーの話)。
  `nightAction` に記録し、同じ夜に2つはできない。ここが機嫌回復と忘却対策の取り合いになる。
- **reward**: 機嫌キープが4日続いた朝だけ挟まる。2択で1つ選ぶと `morning` へ。
- **sleep**: 全員の記憶度を自然減少 → さみしい閾値で無気力判定 → 装備リセット → 翌朝。
  31日目に入る時点で `ending` に遷移し `judgeEnding` を確定させる。

## 感情ゲージの相互作用

| | 効果 | 増える | 減る |
|---|---|---|---|
| がんばる | 収穫 ×1.5 | **夜に「休む」+25 のみ** | 作業 -8 / 就寝 -5 |
| たのしい | 会話成功率 +0.15、作業での消耗が半減 | **会う +20 のみ** | 作業 -12 |
| さみしい | 会って得る記憶度 ×1.4 | 作業 +14 / 装備して就寝 +10 | 会う -30 |

さみしいは「装備するとハイリターンだが、抱えたまま作業すると無気力(80以上)に落ちる」という賭けになっている。
無気力: 収穫0・会話成功率半減・忘却2倍。会えば さみしい が下がるので詰みはしない。

## 忘却の3段階

`stageOf(value)` の1箇所だけで段階を決めている。しきい値は `STAGE_THRESHOLDS`。

記憶度は「**その相手がこちら(りみっち)を覚えている度合い**」。忘れるのは相手の側なので、
カードには相手の本名(`name`)を出し、変化は **相手がこちらをどう呼ぶか**(`callsYou`)で見せる。

| stage | 記憶度 | 表示上の変化(`partnerView`) |
|---|---|---|
| 0 | 70+ | 「りみっち」と呼ぶ / `face: 'full'` / アイドルアニメあり |
| 1 | 40-69 | **「あなた」と呼ぶ** / 見た目は同じ |
| 2 | 15-39 | 「あなた」呼び / `face: 'flat'`(ほお消灯・口は一本線) / アニメ停止 |
| 3 | 0-14 | こちらを知らない / `face: 'blank'`(点目) |

> 当初は相手の名前そのものを「あなた」に差し替えていたが、
> 忘却が2人に進むとカードが「あなた」「あなた」と並んで**誰に渡すのか選べなくなった**。
> 意味の取り違え(こちらが忘れるのではない)とUIの破綻が同じ原因だったので、`name` と `callsYou` に分けた。

stage3 に落ちてから5日以内に会えれば、記憶度が45まで一気に戻る(=「会話ログは一部保持、早期回復可」)。
`MemoryState.resetDay` / `everReset` で管理。猶予切れ後は通常回復のみ。

## 毎日の判断を増やす4つの仕掛け

二者択一だけでは30日が同じ判断の反復になるため、以下を足した。

### 1. 待っている相手(`invitation`)

朝に1人だけ「待っている」相手が提示される。応えると記憶度 ×1.5 と収穫+1、
無視して寝るとその相手だけ追加で -5。**stage3 の相手は誘ってこない**ので、
放置すると誘いの機会そのものが減っていく(=挽回の足場が消える)。
60%の確率で「記憶度が最も低い相手」が選ばれるので、いちばん忘れかけている顔が向こうから来る。

### 2. 思い出(`keepsakes`)

会話がよく通じた日に、低確率(12%〜32%、たのしい依存)で1つ残る。
夜に本人へ話すと **+40** で忘却段階を一気に戻せる切り札。1回で消える。
**同時に3つまで**しか持てないため、「今使うか、もっと危ない日まで取っておくか」が毎晩の判断になる。
相手が完全に忘れると思い出も色あせる(`isFaded`)。記憶度が戻れば色も戻る。

### 3. 伝聞(`BEST_FRIEND`)

ぴす↔まきこ は仲がよく、片方に会って会話が成功すると、もう片方も +5 思い出す。
**とよっぴーは誰の話もしない**ので、とよっぴーに会う日は他の2人が完全に止まる。
「2人まとめて維持する動線」と「とよっぴーに寄る」がはっきり分岐する。

### 4. とよっぴーの「大丈夫だよ」(`whisper`)

夜に選ぶと さみしい -35(無気力の回避に強力)、代償として**全員の記憶度 -4**。
短期的には明確に得なので押したくなるが、8回以上聞くと隠しエンドのフラグが立つ。
とよっぴーが忘れてしまうと選べなくなる = 依存先が消える。

## まきこのご機嫌システム(目的)

### 要求(demand)と、その言い方(demandSaid)

毎朝まきこは4つの要求のどれかを持っているが、**言い方は要求と1対1ではない**。

| セリフ | ありうる要求 |
|---|---|
| 「今日はひま。……べつに来なくてもいいけど」 | 会いに来て / ほっといて |
| 「べつに、いい」 | 会いに来て / ほっといて |
| 「……なんでもない」 | 会いに来て / ほっといて / 何かくれ |
| 「あのお店の前、通った?」 | 何かくれ / 会いに来て |
| 「ぴすは元気にしてるの?」 | ぴすと仲良くして / 会いに来て |
| 「今日はいそがしいから、いい」 | ほっといて |

セリフを覚えても要求は特定できない。これが読み違いを生み、ご褒美「まきこの本音メモ」に価値が出る。
`demandCandidates(said)` が候補を返し、UIは「このセリフの意味は3通りある」と出す。

### 機嫌の増減(夜の就寝時にまとめて判定)

| 出来事 | ごきげん |
|---|---|
| 要求どおりにできた | +14(ぴす関連は+12) |
| 要求を無視した | -12 |
| 「ほっといて」の日に会いに行った | **-20** |
| まきこ以外に会った(会いに来て/何かくれ の日) | -5 |
| スイーツを渡した | +20(「何かくれ」の日はさらに+6) |
| ぴすが取りなしてくれた | +14 / 嫉妬も打ち消す |
| とよっぴーに顔を出した | +8 |
| とよっぴーを4日以上放置 | **毎晩 -12** |
| 朝の突発イベント(30%) | -15〜+10 |

- 機嫌70以上: 全員の忘却が3ゆるやかになる / 仕込み+1 / まきことの会話も伸びる
- 機嫌30未満: まきことの会話成功率×0.6、記憶度回復×0.5(立て直しが重くなる)

### ご褒美(恒久アップグレード)

機嫌70以上で寝た日が**4日連続**するごとに、2択で1つもらえる。
おべんとう(仕込み+2) / 交換日記(忘却-2) / おまもり(成功率+15%) /
お茶の時間(休むで+40) / 写真(思い出+2枠) / **まきこの本音メモ(要求が確定で分かる)**。

続けるほど楽になるので、序盤の数日を耐える動機になる。逆に一度崩れるとストリークが切れて遠のく。

## エンディング判定(優先順)

1. `toyoppi` — とよっぴー偏重(会話の60%以上 or 「大丈夫だよ」8回以上)かつ記憶度80以上
2. `makikoPerfect` — 機嫌85以上(真のクリア)
3. `makikoCold` — 機嫌25以下
4. `forgotten` — 誰か1人でも stage3 のまま終了
5. `makikoOk` — 機嫌55以上
6. `neutral` — 上記以外

## バランス検証の結果(`npm run sim`)

6つの方針 × 5シードで30日を回した実測:

| 方針 | エンディング | ごきげん(5シード) |
|---|---|---|
| 放置(仕事だけ・夜は休む) | makikoCold ×5 | 0〜4 |
| 要求を無視して忘却だけ防ぐ | makikoCold ×4 / neutral | 0〜46 |
| ご機嫌とり(要求どおり+スイーツ+ぴす) | makikoOk ×3 / Perfect / neutral | 52〜100 |
| スイーツだけで機嫌をとる | makikoCold ×5 | 0〜4 |
| とよっぴーに逃げる | toyoppi ×5 | 60〜100 |

調整の経緯:

- 記憶度の自然減少は 6 → 10。6 では「仕事と面会を交互」で全員維持でき、二者択一が緊張しなかった。
- 思い出は入手確率 0.35 → 0.12 + 上限3。当初は30日で20個溜まり、切り札の重みが消えていた。
- 要求充足の機嫌は 18 → 14、ご褒美ストリークは 3 → 4日。18/3日では「要求どおりに動く」だけで
  全シード makikoPerfect になり、緩すぎた。
- **「スイーツだけ」が makikoCold で終わるのが今の設計の要点**。
  スイーツは強力(+20)だが、要求を外した -12 と とよっぴー放置 -12 は埋められない。
  道具に頼るだけでは足りず、その日その日の要求を読む必要がある。
- 「とよっぴーに逃げる」で機嫌が保てるのは抜け道に見えるが、
  「祖母に毎日顔を出していれば母の機嫌も荒れない」という筋は通っているので隠しルートとして許容した。

## スマホ最適化(UI)

`src/ui/` に縦持ちスマホ前提のUIを実装した。`npm run dev` → `http://192.168.0.8:5173/`(LAN内の実機から開ける)。

### レイアウト

3行グリッドで固定し、**スクロールするのは中央だけ**にした。ゲージと操作ボタンが常に見える。

```
┌─────────────┐ ← safe-area-inset-top
│ HUD 日数・ゲージ │ 固定
├─────────────┤
│   .stage    │ ここだけ overflow-y: auto
│  (各フェーズ)  │
├─────────────┤
│ .dock 主ボタン │ 固定・親指の届く下端
└─────────────┘ ← safe-area-inset-bottom
```

### 具体的な対処

| 課題 | 対処 |
|---|---|
| アドレスバーの伸縮で `100vh` が破綻する | `height: 100dvh` |
| ノッチ/ホームバーに被る | `viewport-fit=cover` + 全paddingに `env(safe-area-inset-*)` |
| iOS Safari が入力/ボタンでズームする | 操作系の `font-size` を16px以上 |
| タップが小さい/外す | ボタン最小高 52〜88px、選択肢は全幅カード |
| タップ時の青い矩形・ダブルタップ拡大 | `-webkit-tap-highlight-color: transparent` + `touch-action: manipulation` |
| hover が効かない端末で状態が伝わらない | hover は `@media (hover: hover)` に隔離し、`:active` の縮小で押した感を出す |
| 画面端でバウンドして下地が見える | `body { overscroll-behavior: none }` / `.stage { contain }` |
| 横スクロール発生 | 320px / 375px / 480px超で実測し `scrollWidth === innerWidth` を確認済み |
| 3人カードが狭い端末で潰れる | `repeat(auto-fit, minmax(96px, 1fr))` で自動折り返し |
| 端末のダークモード | `prefers-color-scheme` で全色を変数差し替え、`theme-color` も両対応 |
| 「視差効果を減らす」設定 | `prefers-reduced-motion` でアニメを実質停止 |
| 横向きで操作部が潰れる | `orientation: landscape and max-height:480px` でHUDを圧縮 |
| PCで開くと間延びする | `max-width: 480px` で中央寄せ(スマホ幅を基準に保つ) |

### 表情差分(設計メモ③の受け口)

`src/ui/Character.tsx` が `characters.svg` を「体」と「表情」に分解済み。
`partnerView().face` の `'full' | 'flat' | 'blank'` で口・ほお・目の大きさが切り替わり、
`animated: false`(段階2以降)で ゆれ・まばたきが止まる。カードは `filter: saturate()` で彩度も落ちる。
つまり**忘却の進行が、文字を読まなくても見た目で分かる**。

## 未実装・次の一手

- **がんばるの回復手段がない**。就寝で戻すか、夜に「休む」選択を足すか要判断(現状は30日かけて枯れていく)。
- **段階1(「あなた」呼び)の見た目が段階0と同じ**。呼び名だけの変化なので、
  スマホの小さいカードでは気づきにくい。目の位置を少し下げる程度の差分を足す余地がある。
- **プレイヤーの扱い**: 設計メモは「4キャラそれぞれに記憶度」だが、りみっちを操作キャラと解釈して
  記憶度は他3人に持たせた(`PartnerId`)。りみっちも忘れられる側にするなら
  `PLAYER_ID` と `PARTNER_IDS` を変えるだけで対応できる形にしてある。
